# 人生弹幕机终章峰终体验实现拆解

日期：2026-05-24  
对应交互稿：[2026-05-24-终章峰终体验交互稿.md](</D:/AI try/vibe coding/人生弹幕机/plans/2026-05-24-终章峰终体验交互稿.md>)

## 1. 这份文档解决什么

上一份稿子已经把“终章要带来什么感受”定下来了，这一份只解决一件事：

**怎么把终章模式落成一个可开发、可迭代、不会把主流程搅乱的前端支线。**

目标不是一次做满，而是：

- 不破坏现有 `echo -> revealed -> farewell` 主流程
- 用最少的新状态跑通第一版终章
- 让后续继续加 mood 分支、专用文案字段、移动端优化时不需要推翻重来

## 2. 建议状态流

当前 `viewStage` 在 [appStore.ts](</D:/AI try/vibe coding/人生弹幕机/client/src/store/appStore.ts>) 里是：

- `landing`
- `composing`
- `echo`
- `revealed`

建议第一版新增：

- `finale`

于是完整状态流变成：

1. `landing`
2. `composing`
3. `echo`
4. `revealed`
5. `finale`

### 2.1 状态切换规则

#### 正常分析完成

- `AnalyzeButton`
- `setResult(result)`
- 自动进入 `echo`

这部分保持不变。

#### Echo 倒计时结束

- `echo -> revealed`

这部分保持不变。

#### 用户点击终章入口

- `revealed -> finale`

#### 用户在终章点击“再留一句”

- `finale -> reset() -> landing`

#### 用户在终章点击“重看这一幕”

- 保持 `finale`
- 通过本地组件状态重播，不需要切换全局 `viewStage`

### 2.2 为什么第一版只加一个全局 stage

因为终章本质上是一个整页覆盖层，不是结果页里的某个局部开关。  
把它加进 `viewStage` 会比在 `revealed` 里临时塞一个 overlay 布尔值更清楚，也更方便后续处理：

- 键盘返回
- 禁止背景滚动
- 页面级入场退场
- reduced motion 降级

## 3. 组件结构建议

第一版新增组件建议如下：

- `client/src/components/FinaleOverlay.tsx`
- `client/src/components/finale/FinaleDanmakuBurst.tsx`
- `client/src/components/finale/FinaleWordFlash.tsx`
- `client/src/components/finale/FinaleWhisper.tsx`
- `client/src/utils/finale.ts`

### 3.1 FinaleOverlay

职责：

- 承接全屏层
- 管理时间轴阶段
- 统一读取 `result`
- 处理关闭、重播、再留一句
- 控制背景压暗和白幕覆盖

建议 props：

- `onReplay: () => void`
- `onReset: () => void`

也可以不传 props，直接从 store 读，但第一版更推荐在组件内部直接调用 store，少传递一层。

### 3.2 FinaleDanmakuBurst

职责：

- 渲染终章第二段的全屏弹幕
- 根据选中的弹幕列表生成近景、中景、远景三层
- 只负责飞字，不管白幕和最后一句

输入建议：

- `items: string[]`
- `mood?: string | null`
- `phase: 'idle' | 'burst' | 'fade'`

### 3.3 FinaleWordFlash

职责：

- 渲染第三段的人设词掠影
- 负责词大小、位置、清晰度、延迟、掠入方向

输入建议：

- `words: { text: string; weight: number }[]`
- `phase: 'idle' | 'flash' | 'fade'`

### 3.4 FinaleWhisper

职责：

- 渲染第五段中央治愈句
- 负责最后两个按钮
- 负责结尾留白和视觉稳定

输入建议：

- `text: string`
- `visible: boolean`
- `onReplay: () => void`
- `onReset: () => void`

## 4. 时间轴建议

第一版不要把时间轴拆得太碎。  
建议在 `FinaleOverlay` 内维护一个简单枚举：

- `prelude`
- `burst`
- `wash`
- `whisper`

这里把“弹幕冲出”和“词云掠影”都归在 `burst` 阶段里，通过内部 delay 错开，不必再额外加一个全局 `flash` 阶段。

### 4.1 推荐时序

- `prelude`: `0ms - 600ms`
- `burst`: `600ms - 4600ms`
- `wash`: `4600ms - 6200ms`
- `whisper`: `6200ms+`

### 4.2 为什么不需要更细

第一版最重要的是让整体感觉成立，不是做时间轴编辑器。  
阶段越细，全局状态越多，越容易让组件互相打架。

## 5. 数据准备策略

建议新增 [finale.ts](</D:/AI try/vibe coding/人生弹幕机/client/src/utils/finale.ts>)，只做“终章素材准备”。

建议放这些函数：

- `pickFinaleDanmaku(texts: string[], mood?: string | null): string[]`
- `pickFinaleWords(words: { text: string; weight: number }[]): { text: string; weight: number }[]`
- `getFinaleWhisper(result, fallbackFarewell): string`
- `isSoftFinaleMood(mood?: string | null): boolean`

### 5.1 pickFinaleDanmaku

目标：

- 从 `result.danmaku` 里挑出最适合终章的 `12-18` 条

第一版简单规则就够：

- 优先保留长度适中的句子
- 删掉太像标签或太短太空的句子
- 去掉重复度太高的句子

### 5.2 pickFinaleWords

目标：

- 从词云里挑 `8-14` 个最适合掠影的词

第一版简单规则：

- 先按权重排序
- 去掉特别普通、画面感弱的词
- 保留强情绪词和具象词

### 5.3 getFinaleWhisper

第一版优先级：

1. 当前 `farewell`
2. `movieScene.tagline`
3. `diagnosis.summary` 截短

后续如果服务端加字段，再改成：

1. `result.finalWhisper`
2. 其他兜底

## 6. App 层怎么接

当前 [App.tsx](</D:/AI try/vibe coding/人生弹幕机/client/src/App.tsx>) 里，结果页底部 farewell 区域已经是很好的终章入口位置。

建议改动：

### 6.1 在 `viewStage === 'revealed'` 时

保留结果页和 farewell 区域，但按钮改成两层：

- 主按钮：进入终章
- 次按钮：直接再留一句

推荐文案：

- 主按钮：`离开前，让这些字再经过我一次`
- 次按钮：`再留一句`

### 6.2 新增 finale 分支

在 `AnimatePresence` 里新增：

- `viewStage === 'finale' && hasResult`

渲染 `FinaleOverlay`

### 6.3 关于返回结果页

第一版终章结束后，不一定要给“回到结果页”。  
因为终章本身就是收尾动作，重心应放在：

- `再留一句`
- `重看这一幕`

如果确实需要保留，也放得更轻。

## 7. 第一版动画职责划分

### 7.1 App 负责

- stage 切换
- 页面级淡入淡出

### 7.2 FinaleOverlay 负责

- 全屏遮罩
- body scroll lock
- 时间轴阶段
- 白幕覆盖强度

### 7.3 子组件负责

- 各自文字动画
- 各自内部的 delay 和层次

这个边界很重要。  
不要把所有 motion 状态都堆到 `App.tsx`，不然后面一改就会失控。

## 8. 第一版视觉行为细节

### 8.1 背景

终章打开时：

- 背景继续用现有 mood 背景
- 但整体压暗、加轻微 blur
- 不需要另外换整套背景

这样能保持“还是刚才那次体验”的连续感。

### 8.2 白幕

白幕建议不是纯白 `#fff`，而是偏暖、偏雾一点：

- `rgba(255,255,255,0.72)` 起步
- 再叠一层很淡的暖灰或米白渐变

### 8.3 终句

终句建议最大宽度收在：

- `max-w-2xl` 左右

不要让句子横向铺太满，不然没有“沉下去”的感觉。

## 9. 第一版开发顺序

推荐按下面顺序做，不要并行乱开：

1. 改 store，新增 `viewStage: 'finale'`
2. 在 `App.tsx` 挂上 `FinaleOverlay` 分支
3. 先做一个最简 `FinaleOverlay`
4. 只实现背景压暗 + 白幕 + 最后一句
5. 再接入弹幕冲出
6. 再接入词语掠影
7. 最后补终章入口文案和按钮层级

### 9.1 为什么先不急着做飞字

因为飞字最容易让人误以为“主体完成了”，但其实真正决定体验成立的是：

- 终章入口位置对不对
- 全屏切入是否顺
- 白幕和最后一句是否接得住

先把收束骨架搭好，再加冲击层，成功率更高。

## 10. 第一版验收标准

第一版不需要追求“极致惊艳”，只要满足这些就算成功：

- 用户知道这是一段主动触发的终章
- 从结果页进入终章很顺
- 能明显感到“字从模块里冲出来”
- 白幕能把情绪收住
- 最后一行话能稳稳落下
- 终章结束后，用户知道自己下一步能做什么

## 11. 第二版迭代方向

第一版跑通后，再考虑这些：

- 按 `mood` 分支不同强度
- 服务端新增 `finalWhisper`
- 移动端弱化版专门调参
- `prefers-reduced-motion` 降级
- 更精细的选句和选词逻辑
- 终章中极少量粒子或景深增强

## 12. 推荐结论

这条支线的正确做法不是一次堆满，而是先把骨架做对。

对这个终章来说，真正的主次关系是：

1. 状态流清楚
2. 进入与收束顺
3. 最后一句成立
4. 飞字和词影再去加分

如果按这个顺序做，第一版就已经能有很强的记忆点，而且不会把你现在已经很顺的主流程弄乱。
